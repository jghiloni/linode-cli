## linodectl idp-configuration post-idp-config

Create an IDP configuration

### Synopsis

__Beta__ Creates an external identity provider (IDP) configuration for the account. You can have only one configuration per account. To learn more about the single sing-on for Akamai Cloud, including emergency access accounts setup, see [Single Sign-On](https://techdocs.akamai.com/cloud-computing/docs/single-sign-on-cm). **Prerequisite** You need to have IDP metadata from your identity provider. To create the IDP configuration: 1. Provide a unique label for the configuration. 1. To activate the SSO, set `enabled` to `true`. 1. Enforce SSO for all users of your account with `enforce` set to `true`. The enforcement doesn't apply to [excluded users](https://techdocs.akamai.com/linode-api/reference/get-idp-config-users-excluded). > blue-book > > Set the enforcement to `false`, if you want to test SSO on a small subset of users. After you create this configuration, [add the included users](https://techdocs.akamai.com/linode-api/reference/put-idp-config-users-included) and test the login flow. If the test is successful, enforce the SSO login for all users with the [Update an IDP configuration](https://techdocs.akamai.com/linode-api/reference/put-idp-config) operation. 1. Specify the SAML configuration settings with details from the IDP metadata you got from the identity provider. > thumbs-up There's a tutorial > > We offer an example API [workflow](https://techdocs.akamai.com/linode-api/reference/configure-sso-login) you can follow to create an IDP configuration, test it, and configure an account with emergency access. > blue-book > > This operation is in Beta and available from the `v4beta` URL. **Permissions and scopes** To call this operation, you need permissions, based on the model you're using: - **Identity and access permissions**. Your user needs a role with these permissions. [Learn more](https://techdocs.akamai.com/cloud-computing/docs/identity-access-cm-available-roles). - Permissions: `create_idp_config`
